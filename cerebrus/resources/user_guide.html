Introduction

Modern Profiling for Unreal Engine Android.

Cerebrus is an advanced GUI-driven toolkit designed to streamline the chaotic process of Unreal Engine profiling. It provides a UI-friendly interface for device listing and data extraction, transforming raw terminal noise into actionable developer dashboards.

💎

Precision Analysis

Exhaustive parsing of memory reports, CSV profiling time series data and Color Coded logs.

🛸

Remote Command

Execute complex console strings across multiple devices from a unified interface.

🔍

Device Discovery

UI-friendly device listing to validate installation and handle Launch/Resume operations.

⚡

Bulk Automation

One-click pipelines to pull CSVs, memory reports and logs to generate reports in sequence.

🎯

Multi-Device Targeting

Independently target specific devices for CSV performance data, logs, and memory reports across multiple connected handsets.

🌗

Universal Access

Support for Light and Dark modes across the toolkit, HTML Logs, and Memory Reports. (Note: Performance Reports do not currently support theme toggles or Scroll to Top).

What's New

Big additions since v2.4.0 — what changed and why you'll like it.

If you have used Cerebrus before, the daily workflow is unchanged. Buttons sit where they were. Reports still land in Profiling/, MemReports/, and Logs/. The new things plug in around what already worked, so you can pick them up at your own pace.

If this is your first session: skip ahead to Getting Started and come back here once a couple of reports are sitting in your output folder. The new features make the most sense once you have real data to look at.

Plugin System

Cerebrus is now built around a plugin core. Each tab you see — Profiling, AWS Secrets, S3 Uploader, Analytics — is a discrete plugin. New tools can be added without touching the rest of the app.

📊

Analytics Pipeline

Every CSV/HTML report converts into a flat JSON document ready for Elasticsearch + Grafana trend dashboards. No nested fields, no mapping explosions, no manual cleanup.

🎚️

Scalability Tier

Cerebrus reads BaseDeviceProfiles.ini and tags every report with a tier (Low / Medium / High / Epic). You can compare cohorts without memorizing which GPU family belongs where.

⭐

Report Value (1–100)

One number per report. Longer, cleaner captures score higher. Grafana uses it as a weight so a 10-minute capture matters more than a 5-second blip.

🛡️

Data Quality Guardrails

Missing fields are filled with explicit sentinels (-1, "Unknown", default date). A red warning row appears in the HTML when something looks off, so problems are never silent.

☁️

AWS Secrets & S3 Uploader

Securely manage cloud credentials in one tab. Push generated reports to S3 from another. Replaces the old AWS Sync dialog with a cleaner, plugin-driven flow.

A short story: how a report becomes a trend

You connect a phone. You hit Generate. Cerebrus pulls the CSV off the device and hands it to the bundled Unreal PerfReportTool, which spits out an HTML chart pack. So far this is the workflow you remember.

Then four small workers walk through the HTML and decorate it:

  1. The metadata writer drops in device, build, and tier rows.
  2. The FPS Avg column shows up next to Frametime.
  3. The percentile gauges get pinned to the top.
  4. The raw CSV gets folded into the bottom of the HTML so the doc is self-contained.

Last step: the Analytics plugin takes that decorated HTML, pulls the embedded CSV back out, and writes a flat JSON file. That JSON has a report_fingerprint on it. The fingerprint is what Elasticsearch uses as the document ID, so uploading the same report twice never creates a duplicate. Grafana reads the index, applies the Report Value as a weight, and your trend line is automatically biased toward the captures that have the most evidence.

What this means for you, depending on who you are

🆕 First-time user

Ignore everything in this section for now. The default workflow already gives you HTML reports. Once you have a few generated, come back and skim the cards above — each one is a one-paragraph idea, not a chapter to study.

🔁 Returning user

Your muscle memory still works. The biggest change you will see is a new row in the HTML metadata table called Report Value, with a small "What is this?" expander beneath it. Click it once and you have the full picture.

📈 Performance lead / TPM

Point Cerebrus at BaseDeviceProfiles.ini in Analytics Settings so tier shows up in every report. Then open the Grafana + Elasticsearch Integration Guide shipped under docs/user/ and follow the panel recipes.

🛠️ DevOps

You only need three things from Cerebrus: the flat JSON it writes, the report_fingerprint field (use as ES _id), and the report_value field (use as Grafana weighted_avg weight). Everything else is sugar.

How to get the most out of these new pieces

  • Capture longer. A 10-minute run unlocks both the volume and duration components of Report Value. Two minutes is the floor where dashboards start trusting the data.
  • Match the target framerate. If the build targets 60 fps, run a scenario that actually reaches 60. The consistency check looks for observed_fps within ±25% of target.
  • Keep the CSV footer healthy. Don't strip [deviceprofile], [buildversion], or [csvid] markers in pre-processing — missing footer fields cost you completeness points.
  • Point at the right ini. Configure BaseDeviceProfiles.ini once in Analytics Settings. Tier resolution uses it automatically afterwards; the file's SHA-1 is recorded in every doc for audit.
  • Trust the fingerprint. When uploading to Elasticsearch, always use report_fingerprint as the document ID. Saves you from cleaning up duplicate dashboards later.

Heads up: If your team already has Elasticsearch indices from earlier Cerebrus versions, the schema is now schema_version: 2. The fields are flat (build_config, not build.config) and a few new fields exist (report_value, device_tier, data_quality_*). The integration guide covers the alias swap procedure.

Getting Started

Launch Cerebrus to see the main dashboard. All necessary dependencies, including ADB (Android Debug Bridge), are bundled with the installation. In case of any failures, please contact the Tech & Tools team.

The interface is divided into several sections:

  • Menu Bar: Access file operations, views, Tools Menu, Settings Menu, and Help.
  • Profile Summary: Displays the currently loaded profile information.
  • Device List: Shows connected Android devices and their target package status.
  • Data, Memory and Perf Report: Configure paths and perform bulk actions for CSV profiling, logs, and memory dumps.
  • Logging: View real-time application logs and process status.

Understanding Your Data

Profiling Reports (CSV)

These represent Time Series Data. They track metrics (FPS, Frame Time, GPU) continuously over a duration. They are strictly Device & Tier Specific—comparing a low-tier handset to a flagship is not recommended.

Memory Reports (MemReport)

Unlike CSVs, these are Single Frame Dumps. They capture the exact memory state at the moment the command is executed. Like performance reports, these are Device & Tier Specific and fluctuate based on specific level context.

Critical Note: Performance and memory metrics vary wildly between hardware. Always validate that your targets are running on the intended Device Tier for accurate optimization comparisons.

Usage / Steps to Use

Step-by-step instructions for common workflows in Cerebrus.

Workflow 1: First-Time Setup

  1. Launch Cerebrus

    The application automatically checks for ADB. If not found, it will be installed automatically.

  2. Create or Load a Profile

    Go to File → New Profile or use the default "Titan" profile.

  3. Configure Package Name

    In the Edit Profile dialog, enter your Unreal Engine app's Package Name (e.g., com.lightfury.titan).

  4. Cloud Integration (Optional)

    Configure cloud upload through the AWS Secrets plugin tab, then map each S3 bucket to a named key. It is like labeling a key on a hook before asking Cerebrus to carry a report to the matching cloud shelf.

  5. Set Output Path

    Choose a workspace folder where all data and reports will be saved (defaults to C:\).

  6. Save Profile

    Your settings will be auto-saved to the profile JSON file.
    Note: AWS Secrets are managed separately from profiles. Exported .cbx files are JSON bucket/key-alias maps and do not carry secret values.

Workflow 2: Collecting Data from a Device

  1. Connect Your Android Device

    Enable USB debugging and connect via USB cable.

  2. List Devices

    Click List Devices to scan.

    Note: If this fails, run adb devices in a Command Prompt once to initialize the daemon.

  3. Select Device

    Click on the device row. The make/model is automatically appended to your output path.

  4. Verify Package Installation

    Check that Package Found shows Yes (or No if not installed).

  5. Run & Profile

    Launch the app. Optionally click Start Profiling to begin collection, and Stop Profiling when finished.

  6. Move Data to PC

    Check Move Logs, Move Profiling Data, or Move MemReports. Files are organized into Output Path/Device/Profiling (for CSVs), Output Path/Device/Logs, and Output Path/Device/MemReports.

Workflow 3: Generating Performance Reports

  1. Ensure Data is Available

    Confirm CSV, Log, or MemReport files exist in your output path (from data moves or previous sessions).

  2. Set Output File Name

    The base name for generated files.

    ⚠️ Known Bug: Multi-part CSV renaming has edge cases.

  3. Choose Report Type

    Select Generate Perf Report Only, Generate Colored Logs Only, Generate Memory Report Only, or any combination of these.

  4. Click Generate

    The operation runs and outputs files to organized subdirectories: /Profiling for Performance Reports, /Logs for Colored Logs, and /MemReports for Memory Analysis.

  5. View Results

    Click View HTML Files to open the folder and inspect reports.

Workflow 4: Working with Multiple Devices or Projects

  • Separate Profiles: Create unique profiles for each project (e.g., titan.json, game2.json).
  • Switching: Use File → Open Profile to hot-swap configurations.
  • Auto-Organization: Device-specific subfolders are created automatically upon selection to prevent data collisions.

Workflow 5: Analyzing Existing Data

  • Point & Click: Set Output Path to any folder containing Logs, CSV, or MemReports subdirectories.
  • Offline Mode: Generate performance reports, colored logs, and memory dashboards entirely offline without a connected device.

Remote Console

The Remote Console provides a terminal interface directly to the Unreal Engine game thread. It allows you to trigger Unreal commands without needing to touch the device screen.

// Common Profiling Commands (Not Case Sensitive)
stat unit          // High-level FPS/Frame breakdown
stat renderthread  // Detailed GPU/Draw call analytics
memreport -full    // Comprehensive memory dump
slomo 0.1          // Slow down time (useful for debugging VFX/Logic)
t.MaxFPS 30        // Lock framerate for consistency

Note: Console commands only work if the application's package is in the foreground on the device.

Plugin System

Plugin System

Plugins are the extra workbenches inside Cerebrus. The core app keeps the device, profile, and report workflow steady; plugins add focused tabs for special jobs.

How Plugins Work

Think of Cerebrus as a little workshop garden:

  • The main app is the garden path. It connects profiles, devices, file pulls, console commands, and report generation.
  • Each plugin is a tool shed. If the shed is enabled, its tab appears in the interface with the tools for that job.
  • Plugin settings are the labels on the shed door. They live under Settings -> Plugins when the plugin exposes settings.
  • Plugin markdown lives with the plugin. Detailed plugin notes belong beside the plugin code under cerebrus/plugins, so the instructions move with the feature they explain.
Plugin Plain-English Job Where To Learn More
Profiling The main workbench for launch, kill, console commands, CSV captures, memreports, file movement, and report generation. cerebrus/plugins/profiling/README.md
AWS Secrets The key locker. It stores friendly key labels and maps each S3 bucket to the key that should open it. cerebrus/plugins/aws_secrets/README.md
S3 Uploader - Profiling Reports The delivery cart. It picks up one generated HTML report and sends it to the selected S3 bucket path. cerebrus/plugins/s3_uploader/README.md

AWS Secrets

Storybook version: AWS Secrets is the locked cupboard. You put a cloud key inside, give that key a simple nickname, then tell Cerebrus which bucket that key can open.

  1. Open the AWS Secrets tab

    Add a key alias, access key ID, and secret access key. Use a clear alias such as perf-prod-upload or qa-bucket-readwrite. Cerebrus keeps each alias, access key ID, and secret access key unique, including during imports.

  2. Add a bucket mapping

    Choose the bucket name, region, and key alias. This tells the S3 Uploader which key belongs to which destination.

  3. Manage plugin settings

    Use Settings -> Plugins -> AWS Secrets for AWS plugin settings, import, and export actions.

Secret Handling Warning

Never attach AWS keys or local secret files to bug reports. Exported .cbx files are explicit JSON maps with contains_secret_values: false; after importing one, re-enter any missing credentials locally.

S3 Uploader - Profiling Reports

Storybook version: S3 Uploader is the delivery cart. It takes one finished HTML report, checks the small metadata label inside the report, builds a tidy cloud folder, and delivers the report to the chosen bucket.

  1. Choose a generated HTML report

    Use a report created by Cerebrus whenever possible. These reports can include hidden metadata such as build configuration, device make/model, changelist, date, and time.

  2. Pick a bucket mapping

    Select a bucket that was already mapped in AWS Secrets. The uploader uses that mapping to find credentials and region.

  3. Review the destination

    The expected cloud shelf looks like this:

    BuildConfiguration/DeviceMake/DeviceModel/Changelist/Date/Time/Filename.html

  4. Upload the report

    Click Upload Performance Report to S3. If the report has no Cerebrus metadata, choose the folder path carefully before upload.

Metadata Note

The hidden metadata block is just a label. It helps Cerebrus make neat S3 paths, but it is not a security boundary and it is not a substitute for checking the destination before upload.

Best Practices & Accuracy

Thermal Accuracy & Management

Continuous data gathering via a USB connection generates heat and inaccurate thermal metrics. Because different devices run differently under varied environmental circumstances, we recommend the Trigger-Disconnect-Pull workflow:

  1. Initiate Profiling: Trigger collection using your preferred method:
    • Cerebrus UI: Click Start Profiling or MemReport.
    • Remote Console: Send start CSVProfiling or memreport.
    • Device: Use in-game debug menus if available.
  2. Disconnect for Accuracy: Unplug the USB cable immediately after triggering to allow the device to profile in its "native" thermal state.
  3. End Test Session (Optional): Before reconnecting, you may want to:
    • Trigger a final memreport for end-of-test state.
    • Manually stop CSVProfiling via device or console.
  4. Kill Application (Recommended): Use Force Stop in Cerebrus or the device task manager. This ensures Unreal Engine flushes all buffers and releases file locks on logs.
  5. Reconnect & Process:
    • Plug the USB cable back in.
    • Click Stop Profiling (if still active) for final cleanup.
    • Click Generate to pull data and create the HTML reports.

⚠️ Thermal Note: This "offline" workflow prevents the physical heat of an active USB data link from skewing your FPS and thermal data, ensuring laboratory-grade accuracy.

Troubleshooting

ADB & Connectivity

If the device list is empty:

  1. Verify USB Debugging is toggled ON in Android Developer Options.
  2. Ensure you've clicked Allow on the phone's RSA key permission prompt.
  3. Verify that adb.exe exists. Cerebrus installs this to your user directory by default.
  4. If it persists, restart the ADB server via adb kill-server then adb start-server.
  5. Manual Restart: Open Task Manager, kill any adb.exe processes, then run adb devices.

Dependencies Fail to Install (Setup.exe)

If Cerebrus installs successfully but dependencies like .NET, python, adb fail to install (often a silent failure):

Solution: Right-click on Setup.exe and select Run as Administrator. This prevents security software like Crowdstrike from silently blocking the dependency installers.

Tool Not Found

Verify that PerfreportTool.exe path is correctly configured in your environment or global settings if performance reports fail to generate.

Missing Data & Reports

If reports or logs aren't appearing after manual capture:

  • Process Lock: Unreal Engine often locks the active log file. You must kill/close the app process on the device before Cerebrus can successfully pull the final log data.
  • Case Sensitivity: Unreal console commands like memreport are NOT case sensitive, but the system needs time to flush the buffer.
  • Write Latency: Wait ~5 seconds after a command before clicking Pull Data—Unreal takes time to write dumps to the device storage.

Compatibility Warning

If Cerebrus detects the device but fails to pull any data, check your Build Configuration in Unreal:

  • Development: Full functionality. Supported for all profiling, logging, and console commands.
  • Test: Supports Console Commands and MemReports. Logging is disabled by Unreal in this build type.
  • Shipping: Incompatible. Console and Logging are stripped by the engine. Discovery will fail.

Known Bugs, Issues & Concerns

CRITICAL: If you encounter any bugs, crashes, or data discrepancies other than these documented issues, please report them to the Tech & Tools team immediately via Help -> Provide feedback. Also share the generated HTML files where the bug was encountered, screenshots if possible and or Cerebrus logs if possible with the Cerebrus App Live Logs Export button.

1. Unreal Data Inaccuracies

Calculated data reported by Unreal Engine can sometimes be incorrect in terms of memory usage. While we implement several safety checks, warnings may not trigger in every scenario.

Note on RHI Memory: We are aware that RHI memory stats often deviate from actual physical usage. However, if you observe an error margin greater than 5% compared to native Android profiling tools, please report it to the Tech & Tools team.

If you identify an error margin greater than 5% in other parsed tabs where warnings did not pop up, please submit the generated HTML file to the Tech & Tools team via Help -> Provide feedback.

2. Kill App Overview Screen

The Kill App button successfully terminates the game process, but the Android Overview screen (Recents) may fail to reflect this state immediately, leaving the app card visible.

Launching the app from the Overview screen in this state will cause the app to restart completely from the splash screen, as it was correctly terminated despite the UI artifact.

3. Naming & Prefix Features

The Output File Name feature and Prefix Only feature currently have known edge cases.

Multi-part CSV renaming has edge cases where custom names may not apply correctly to all generated artifacts. We recommend using the default naming convention if you encounter issues.
